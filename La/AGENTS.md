# 本地论文工作区协作规则

每次工作：
1. 阅读根目录 AGENTS.md 和 papers/papers.yaml。
2. 确认目标课题、投稿版本及该版本 README.md。
3. 检查默认主文件、真实编译目录和当前改动（有 Git 时先 git status/diff）。
4. 根据用户请求执行最小必要修改。
5. 运行目标版本编译，检查相关输出；只读任务不运行会产生文件的编译。
6. 记录修改和验证结果，报告实际 PDF 路径及剩余问题。

## 任务边界

- “只讨论”“只阅读”“先分析”时保持只读。
- 工程搭建或编译修复不包含主动重写论文正文。
- 明确要求润色、改写或补充正文时才修改对应内容。
- 不随意更改 notation、citation key、label、公式或脚注。
- 不编造参考文献、实验结果和研究结论；未知内容标为待补充或待验证。
- 多个候选主文件先判断并记录，不擅自覆盖或切换默认稿件。
- 优先通过搜索路径、包装入口和软链接修复工程，避免拆散原始工程。
- 保留已有文件和未提交改动。常规创建、检查和可逆修复直接执行；缺少关键输入或涉及覆盖、删除已有内容时询问。用户已授权的生成缓存清理无需重复询问。
- 新投稿版本使用独立目录，不覆盖旧版本。官方模板保存原始副本，记录来源、适用年份、获取日期和核验状态；不以旧年模板冒充当前模板。

## 编译失败排查顺序

1. 参考文献路径与工具链。
2. sty/bst/cls 等依赖和搜索路径。
3. 图片相对路径。
4. 主文件与编译根目录是否一致。
5. 宏包、字体和排版引擎要求。

## 工程约定

- topics/ 是权威组织入口；papers/、assets/、src/ 是相对软链接，不建立同步副本。
- 元信息 papers/papers.yaml 使用 JSON 语法（YAML 1.2 的子集），由 Python 标准库读取；保持该语法，不添加 YAML 注释。
- scripts/common.py 是主文件、编译根目录、输出路径的唯一解析模块。不要为编辑器另建编译链。
- 显式主文件相对 compile-root 解析；默认入口按 default-main 解析。实际入口的文件名决定 PDF 名称。
- 输出集中在版本 build/，启用 SyncTeX。用 ./paper preview ID --viewer none 查询上次成功产物，不从多个 PDF 中猜测。
- 编辑器自动保存构建与命令行 watch 二选一。不开机或打开工作区自动运行 watch。
- 新建文件目录、脚本/结构/入口修改、依赖路径修复、主文件切换、编译成败均记录日志。
- 框架级写 logs/project_log.md，论文级写版本 logs/change_log.md，跨层同时记录；已有自动日志不重复追加。

日志格式：
```
## [YYYY-MM-DD HH:MM +ZZZZ] 操作类型
- object: 操作对象
- action: 具体操作
- status: success | warning | failed
- note: 验证结果或待处理事项
```

Git 追踪源码、最终图片、参考文献、必要模板、脚本、配置、说明、元信息和日志；忽略 build、中间文件、缓存、大型原始素材、临时提交压缩包、实验数组和模型权重。不盲目 git add -A，不自动提交、推送或发布。
